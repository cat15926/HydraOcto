# 持续协作平台正式实施指导

本文是代码仓内正式开发依据，收录已确认的持续协作方向、协作主干规则和 N0–N7 实施范围。实施进度与实际限制统一维护在[实施进度](implementation-progress.md)。产品设计与当前架构概览见[项目 README](../README.md)。

确认依据为此前确定的五项主干规则，以及用户明确启动 N0–N2 的开发指令。2026-11-04 用户继续实施计划，按阶段顺序启动 N3，第 9 节细化其执行约束。2026-11-05 用户明确启动 N4，第 10 节收录任务和正式交接规则；同日明确启动 N5，第 11 节收录产物、交互、评审与受管作业规则；2026-11-06 启动 N6，第 12 节细化调度、多来源和多人征询；同日明确启动 N7，第 13 节收录日常工作台与成员账户约束；其他阶段不自动扩大范围。产品版本、规则版本和计划版本分别维护：当前产品为 0.8.0，上一已验收基线为 0.7.0，沿用 0.6-rules 的相关规则，N0–N2 来源计划为 0.7-plan。

## 1 目标与范围

建设本地单用户的多 Agent 持续协作平台。用户在长期保留的公共会话中自然发送消息、追问或点名成员；成员依据自己的职责和准确请求调用工具、请求同伴协作。普通聊天不设置永久负责人，不强制用户先选择接收人、消息类型或控制动作。

成员、运行时、认证方式和模型分别配置。优先支持 Codex app-server 与 Claude Code CLI，允许官方登录和 API 密钥接入；直连 OpenAI-compatible、Anthropic API 为独立承载。配置路径可用不等于所有认证组合或供应商能力都已完成实机验收。

采用独立设计和实现。Clowder 只作为业务行为研究对象，不搬迁其源码、Prompt 或品牌素材。本轮使用 TypeScript、React、Node.js 24、SQLite 和 SSE；沿用现有来源调度和单进程数据库租约。

## 2 已确认的协作规则

| 规则 | 实施要求 |
| --- | --- |
| 来源级调度 | 一个逻辑来源保存准确目标，各目标拥有自己的投递责任；来源顺序和成员占用共同决定准入。同源成组等待，共享目标不能越过前源，独立目标可以继续执行 |
| 批次执行模式 | 模式由本次实际新建执行的目标数决定，持久保存在 Batch 并传给每个成员。并行批次的最终文字提及不自动接力；合法结构化协作请求仍可独立准入 |
| A2A 失败回报 | 只有准确 caller、来源、回复及消费关系成立时才创建失败控制来源；终态、失败证明和控制来源原子提交，重复提交不重复派发，失败回报不递归制造同类回报 |
| 投递到执行的责任迁移 | Delivery、Response 和 Consumption 精确关联。投递退出队列证明输入已有承接关系，不证明供应商接受、模型完成或 Task 所有权转移 |
| 承载接受证据 | prepared、平台 exposed、供应商 accepted、执行结果和真实退出分别记账。超时、stop 意图、同名 session 或 PID 消失不能代替准确证据；未知不自动重发 |

普通 A2A 的成功可以自然结束，不默认回唤调用方；后继工作由新的合法请求、允许的串行文字接力或合格失败回报触发。N6 的活动追加、多来源归并和重排按第 12 节单独验证，实际交付状态以进度文件为准。

## 3 N0 基线与运行契约

使用现有 SQLite 短事务承接领域命令，网络与 CLI 工作放在事务外。迁移保留原会话、成员、账户、来源、投递和执行 ID，不重置用户数据。数据库格式版本与运行规则版本分别管理。

| 持久记录 | 冻结或提交时点 | 关键约束 |
| --- | --- | --- |
| RoutingDecision | 用户来源准入事务 | 固定 targets、理由、策略版本、历史游标与配置修订；幂等重放返回原路由 |
| ExecutionContractSnapshot | 领取并创建 Invocation | 固定成员/账户元数据、规则版本、同伴目录、工作区、历史截止点及来源版本/摘要；密钥仅保留环境引用 |
| InputManifest 与输入正文 | 调用承载之前 | 保存精确输入、表示范围、省略原因、预算、版本及 SHA-256；实际发送使用捕获正文，不按新配置重建 |
| Invocation 版本 | 执行、取消与恢复状态提交 | 分别检查 invocationRevision、cancelRevision、inputRevision，保护迟到结果和并发核查 |
| RecoveryCheck / HoldRecheck | 核查决议事务 | 保存 requestId、预期版本、准确对象、观察与结果；命令重放不重复产生副作用 |

旧数据没有捕获的输入不能事后补造。未发送的 prepared 使用明确兼容处理器继续；不支持的冻结规则阻塞外部发送并说明原因。已越过承载边界的未知调用保留原身份和隔离，不自动重跑。

实现入口：[持久状态与迁移](../server/collaboration/store.ts)、[领域类型](../shared/collaboration.ts)、[服务租约](../server/store.ts)。

## 4 N1 自然协作与输入

路由预览和发送使用同一服务端 resolver。预览只提示当前预计目标；发送在事务中重新计算并冻结。有效显式提及优先，普通无 @ 追问按有效历史点名、健康回复者及合法偏好/默认成员延续；特殊偏好模式按各自规则处理。忙碌成员进入排队，不因忙碌而被隐式替换；已绑定来源和准确 A2A 不扩大目标集合。

接收成员保留自己的身份和权限。平台从持久关系提供准确 parentInvocation/caller、本次请求、同伴职责、批次模式和允许协作对象；正文中的身份声明不能替代真实调用关系，同伴职责不能授予新工具权限。

输入组装保留完整本次请求及必要身份，以明确的保守预算选择公共背景。超过预算或来源已失效时明确失败，不静默截断本次请求。所有同批次成员使用共同历史截止点，防止较晚组装的成员看到同批次先返回的答案。

背景可见与本轮消费分别记录。manifest 冻结背景来源、原目标及其投递状态；背景中的 pending/held 不因目录或省略材料可见而新增本轮 Consumption。N6 新契约可将符合条件的完整来源另行纳入准确请求，并记录独立消费；旧契约维持原行为。发送前再次核对输入/来源版本和摘要。

本轮审计范围是平台提交的 prompt，摘要阶段为 `platform_prompt`；不冒充 CLI 内部上下文或供应商完整请求。工作台提供只读路由提示、材料清单、准确 caller、冻结输入及连续性证据。

实现入口：[自然路由](../server/collaboration/routing.ts)、[输入组装](../server/collaboration/context.ts)、[工作台](../web/CollaborationApp.tsx)。

## 5 N2 核查与恢复

核查先校验幂等身份和预期版本，在事务外读取准确承载观察，再在提交事务复核版本。客户端提供的 observation 不能作为承载证据，真正失去服务租约的进程不得继续提交。

| 已知事实 | 允许的处理 |
| --- | --- |
| 原调用仍被本进程观察为运行中 | 记录观察，不创建第二次调用；运行中不等于已接受 |
| 合格服务中断、未取消、准确终态及退出均已证明 | 经受限恢复迁移更新原回复，保留原中断审计，唯一提交相应失败控制来源 |
| 用户取消，含中断后正在核查的执行 | 递增取消/执行版本，使旧观察失效；迟到成功不能覆盖取消意图 |
| 只确认准确执行退出 | 保存退出证据，保留结果未知，不自动重发 |
| 无查询能力、身份不足、仅超时或连接断开 | 保留 unknown 或 unsupported 的明确理由，不释放未知占用 |
| 原 held 投递重验成功 | 仅恢复该 delivery 为 pending，保留 source/member 身份，继续遵守原来源组及顺序 |

当前 inspect 使用本服务进程中的可靠观察缓存。跨服务重启、缓存丢失或承载缺少准确查询接口时不能推断结果；原生远端查询和会话续接并非 N2 已具备的能力。

实现入口：[引擎](../server/collaboration/engine.ts)、[承载核查](../server/collaboration/inspection.ts)、[命令与 HTTP](../server/collaboration/http.ts)。

## 6 接口与实现顺序

| 接口 | 内容 |
| --- | --- |
| `POST /api/conversations/:id/route-preview` | `{content}`，只预览，不创建来源 |
| `POST /api/conversations/:id/messages` | `content/requestId`，原子保存来源和路由；重放保持原结果 |
| `GET /api/invocations/:id/input` | 读取已捕获的 manifest 和正文；缺捕获时明确显示，不重建 |
| `POST /api/invocations/:id/reconcile` | requestId 与预期 execution/cancel/input 修订；服务端读取证据并提交核查 |
| `POST /api/deliveries/:id/recheck` | requestId 与预期 delivery/source 修订；只重验原 held 投递 |

具体参数名以[共享类型](../shared/collaboration.ts)和[HTTP 实现](../server/collaboration/http.ts)为准。POST 沿用本机 Host/Origin 和 CSRF 校验；工作区访问受目录边界约束，工作区工具只读；任务工具仅修改经过授权的平台任务状态。

维护与后续修订顺序为：先明确规则和验收场景，再修改迁移/版本与来源事务，随后实现路由/输入或核查命令，最后接通工作台并验证对应流程。只在正式指导中收录已确认、可实施的阶段约束；未完成详细设计的后续计划留在本地资料库。

## 9 N3 原生会话延续（2026-11-04 启动）

以会话 × 成员为隔离边界，新建 `cc_native_sessions`，schema 升至 3。每代绑定保存链序、前代、状态、准确原生 ID、上一轮锚点、配置指纹、运行版本及证据引用。Invocation 保存选择计划，发送前重建另记替换事件；旧 0.2.1/0.3.0 契约保持原有 fresh 行为，不从历史同名 session 反推绑定。

兼容指纹覆盖冻结的账户及修订、运行时、模型、成员职责、工具权限、工作区实际目录身份、CLI 版本与配置目录、认证身份。API 凭据只参与不可逆摘要，不保存明文；官方登录使用 CLI 返回的身份元数据，身份不可确定时不复用。默认模型未固定时采用保守新建。运行时在发送前再次核对身份；不兼容时生成新代、封存旧代，保留具体原因与公共历史。

| 条件 | 处理与证据 |
| --- | --- |
| 上一轮成功、已接受且真实退出，指纹相同 | 只允许续接该会话该成员的 ready 绑定；计划与执行身份持久保存 |
| Codex 续接 | `thread/resume` 成功且 `thread/turns/list` 的上一轮与保存锚点一致，才发送 `turn/start`；保存准确轮次证明 |
| Claude 续接 | 仅访问平台自己创建的准确 transcript；当前输入摘要、当前 assistant UUID 与 parentUuid 链可追溯到上一锚点，才标记 resumed；`system.init` 回显 ID 不足以证明恢复 |
| 原生历史缺失或被外部改写 | 输入尚未送出时可以封存并重建；无法确认的协议错误停止本次调用，不自动兜底发送第二次 |
| 取消、失败、未知退出或核查未完成 | 不复用该代；未知占用仍遵循 N2，不因为新增 session 而绕过 |
| 同 ID、无准确恢复证据 | 显示 unknown；保留公共请求和失败/未知结果，不将其改记为已续接 |
| 使用量 | 仅展示承载报告的 tokens/cost 与统计范围，缺失显示未知，原生估算成本不当作账单 |

公共会话继续按 N1 构造不可变输入；原生私有历史不进入公共消息或其他成员输入。每次仍是独立执行，append=false；会话续接不等于恢复未知的在途作业，不增加自动成功回唤。

验收覆盖双 CLI 连续两轮、成员/会话隔离、账户/凭据/模型/目录/权限变更、持久库重启、旧契约兼容、失效历史的发送前重建、迟到与取消保护及会话链/未知用量展示。真实验收用合成工作区中的私有随机标记：首轮通过工具读取但不在公共回复披露，次轮在标记文件移除后回忆，证明结果不是平台公共历史回填。

协议参考：[Codex app-server](https://learn.chatgpt.com/docs/app-server)、[Claude CLI](https://code.claude.com/docs/en/cli-reference)。协议细节以本机安装版和实测证据为准。

## 10 N4 普通任务与同会话正式交接（2026-11-05 启动）

用户明确启动 N4。新增可选普通任务与同会话交接，不要求每条聊天建任务，不把普通 A2A 转成责任交接。跨会话委托、Action holder 与外部条件自动唤醒留在 N9。

### 数据与版本

schema 4 新增 `cc_ordinary_tasks`、`cc_task_handoffs`，沿用原 SourceWork、Delivery、Invocation、Response、Consumption、事件和幂等回执。旧数据不补造任务。任务保存 todo/doing/blocked/done、ownerMemberId、ownerRevision、独立 task revision、executionRef 与最后交接来源。准确执行绑定包含 invocation/response/member/conversation/source/inputRevision 及服务端生成的 fence，原生 session/turn 只作为附加证据，不能代替平台执行身份。

新执行使用 0.5.0 契约与 `readonly-tasks-v1` 工具策略，任务上下文在领取时冻结。旧契约继续保持原工具集合；工具策略变化使旧原生会话按 N3 兼容规则重建。当前任务状态可通过 task_list 显式读取，读取或投影不授予修改权限。

### 规则与操作

- 用户与获授权 Agent 可创建任务。用户可指定同会话成员并生成任务来源；Agent 创建仅可不分配或分配给自己。未分配任务通过合法 doing 更新领取；负责人已有待投递来源时，不通过无关执行抢占绑定。
- 来源领取与任务执行绑定在同一事务，转交应用与新执行启动分别记账。普通 A2A 来源不继承任务绑定，负责人不改变。普通聊天的历史路由不因任务 owner 改变而改变。
- 交接准备保存准确 actor、旧 assignment/executionRef、新目标、来源及预期 ownerRevision。新目标投递先 held，旧执行终态且 teardown confirmed 后才 CAS 应用 owner 并恢复该原投递。无旧执行可立即应用；不增加 awaiting_acceptance。
- 用户可选择停止旧执行后转交；停止请求不释放占用。Agent 发起交接后自然结束当前回复，交接等待其真实释放。用户取消 Agent 的旧执行会使其未应用交接失效；用户明确发起的交接仍按自身意图等待退出，也可单独撤销交接。
- 完成由明确的 task_update done 或用户操作产生。Agent 必须匹配当前 ownerRevision、任务 revision、准确执行与消费来源；旧 owner、其他成员、旧取消代次、旧来源均拒绝。CLI 结束或文本声称完成不改任务 done。done 保留尚未释放的 executionRef。
- task revision 防止并发编辑覆盖；ownerRevision 只在 owner 真正变化时递增。交接幂等重放不重复产生来源或 owner 变化。工具调用标识同时约束工具名和参数，不能换一个任务重复使用。正式交接执行的结束文本若提及同一接任成员，不再重复产生文字接力。任务被完成、明确终结或交接撤销后，相关未消费投递撤回；消费关系及历史证据保留。
- frozen/degraded/abandoned 保存明确原因，表示本次责任跟踪终结，不证明成功或执行退出，不提供通用“恢复暂停”按钮。此类终结操作当前由用户界面/API 发起，Agent 工具只提供四种任务状态。用户可以新发工作或明确重新设置任务，另建合法来源。

### 责任投影与验证

工作台分别显示任务负责人、准确执行者、等待投递目标及等待旧执行释放。投影从持久事实重建，不作为授权来源。dead 表示执行已有终态但退出仍未确认，或失败/中断后任务仍未完成的异常；void 表示未完成任务已无执行和待投递承接；zombie 表示执行长期无可观测进展，仅诊断，不自动释放或重发。阈值为本平台明确的 5 分钟观察窗口，不宣称是 Clowder 的统一阈值。消息按逐目标 Delivery 投影，新来源可形成新的活跃责任。

接口采用独立 `/api/ordinary-tasks` 命名，避免混入 legacy `/api/tasks`。创建在会话下进行，更新/交接命令要求 requestId 与 task/owner 修订；HTTP 沿用 Host/Origin/CSRF，Agent 身份只由当前运行回调绑定，正文不能指定 actor。工具为 task_list、task_create、task_update、task_handoff，继续仅开放工作区读取。

验收覆盖未分配领取、任务绑定、普通 A2A 不转球权、等待真实退出、取消与交接竞态、旧回调拒绝、同命令重放、旧来源失效、权限变化、未知执行隔离、重启续处理、任务 done 与执行释放分离、独立任务并行，以及双 CLI 的真实工具交接与完成。

## 11 N5 版本化产物、精确交互与评审（2026-11-05 启动）

用户启动 N5。本轮实现版本化文本产物、逐次写入审批、固定材料评审与受管写入作业；工作区仍只读。原生任意 Shell、任意文件修改和远端作业不因产物审批获得权限。

### 产物与受管写入

schema 5 增加产物、不可变版本、审批、作业、评审和交互记录。新执行冻结 `managed-artifacts-v1` 工具策略，旧契约保持原权限。产物每版包含完整正文、SHA-256、字节数、基准版本、来源执行/消费/输入/取消代次和可选普通任务 ownerRevision/fence。文本上限 32 KiB；名称仅为展示文件名，不接受目录路径。产物只落入数据目录中的 `collaboration-artifacts`，不修改用户工作区。服务启动前拒绝工作区与受管产物区重叠；每次文件操作逐级拒绝自定义路径中的软链接，重启也不重新信任可变的上级链接。仅按 macOS 固定系统映射规范化 /tmp、/var 别名。

用户逐次批准准确版本与操作摘要；批准不是任意工具授权。审批 24 小时有效；修改正文需提出新版本，旧审批不能复用。基准 head 漂移、来源修订/取消/成员范围变化和任务执行责任变化使未执行审批失效。Agent 成功并确认退出后，尚有效的版本提议可以由用户批准为独立作业，不向已结束的原生调用补发响应。失败或未知执行的提议不执行。

批准先在事务中持久化 jobId、versionId、operationDigest、fence，再由作业处理器在事务外写入不可覆盖的私有文件，校验文件回执后才发布 head。版本内容和回执绑定准确作业。重启时已运行作业只核查原文件：准确完整回执可完成原作业；缺失、部分写入或身份不符保持 unknown，不自动重写。重复终态核查不重复发布或唤醒。显式选择完成通知成员才创建唯一 job_result 来源；普通 A2A 成功仍不自动回唤。

### 固定版本评审

评审请求绑定已发布 versionId/digest、指定同会话另一成员和准确 review SourceWork。领取时冻结评审快照；只有消费该来源的准确运行执行可以通过 review_submit 提交 accept/changes_requested。聊天文字、无关 A2A、旧执行、旧取消代次不能形成评审结论。提交记录保留准确 responseId、inputRevision 和 cancelRevision，当前有效性继续核对这些身份。新版本发布后旧结论保留但不再代表当前版本，未完成旧评审失效。可选代码评审还绑定工作区实际干净 Git HEAD；变脏或 HEAD 改变后不能提交当前有效结论。评审不自动完成普通任务，也不转移负责人。

### 交互与承载边界

平台 user_question 对两类 CLI 可用，记录准确执行、来源、输入修订、参数摘要、问题选项与到期时间。用户回答须匹配交互修订和摘要，取消/退出/超时后的回答拒绝。返回适配器只表示平台响应已交给适配器，不等同原生接受证据。

Codex 的原生 requestUserInput 按安装版协议桥接；原生命令/文件/权限审批在当前只读策略下拒绝并记录，不伪装成受管产物审批。Claude print 承载仅声明平台工具提问，原生交互不声明支持。协议参考：[Codex app-server](https://learn.chatgpt.com/docs/app-server)，以协议测试与实际运行分别说明证据等级。

### 验收

验收覆盖版本并发与幂等、审批越界/过期/取消、原执行结束后的准确授权、路径与软链接防护、文件与数据库故障窗口、unknown 不重写、固定版本评审及失效、任务责任分离、交互超时和迟到回答、旧契约迁移、浏览器操作和双 CLI 有限实机调用。实现自测后冻结源码摘要，交给已建立的 GPT-6.1 Terra 会话独立验收；缺陷修复后重新固定版本复验。

## 12 N6 调度、输入归并与多人协作（2026-11-06 启动）

用户明确启动 N6。执行 N6-A/B/C/D，沿用既有主干规则与独立实现边界。交付产品 0.7.0、schema 6，新契约使用 cooperation-v2；旧契约不扩大权限。不会将队列退休、承载接受、原生读取与业务完成合并为同一状态。

### 调度与取消

来源按已设置 position 优先、position 升序、urgent 优先、入队时间、稳定 ID 排序。排位只控制来源，不能单独重排某个接收者。队列修订及 orderRevision 独立于内容修订，避免重排剩余 sibling 时使已交付正文和授权失效；重排必须 CAS 当前队列修订，领取在同一事务重验实际排序。

普通成组等待、独立目标绕行、全政策 hold 跳过与部分 hold 单目标继续保持。显式 unresolved 用户来源在会话有活动执行时形成后项屏障；空闲后才绑定目标，已 bound 且无剩余责任的来源不再解析。解析失败保留未绑定事实，不伪造接收。仅承载身份探测这种模型发送前的瞬态错误可对原 prepared 执行退避：10 秒起翻倍、最多 60 分钟，进程内状态重启清空；已发送的未知结果不重试。政策 hold 不随时间解除。

单轮停止只取消准确执行。停止当前全部运行针对当时执行建立 60 秒进程内成员 fence；实际退出仍须确认，新用户输入仅清除其目标的抑制，TTL/重启不会恢复已撤回来源。自动链的同内容回到祖先成员请求会被拒绝，合法新内容和已有深度限制分别处理。

### 多来源与失败关系

新契约允许在首次 prompt 全文暴露或 conversation_read 工具完整返回时，将其他合法来源归并到同一 Response。仍只有一个 primarySource；task/review/group 与正在追加的专用来源不通过公共背景归并。只消费准确接收者的 Delivery，不消费 sibling。被裁剪、仅摘要/目录出现的材料仍只是背景；完整读取会留下正文、摘要、来源修订、response/inputRevision 与消费路径的独立记录。

工具 conversation_pending 查看本成员可读待办，conversation_read 一次最多完整读取 8 条、总字节数受限。sourceIds 只选择集合，不改变来源顺序；首次全文归并和工具返回/消费均使用当前来源排序。归并和 inputRevision、Consumption、失败 caller 资格及逐目标退休同事务；已有准确消费但尚未退休的投递按原事实修复，不新建调用。失败从全部准确来源重算 caller，唯一失败控制来源可以有多个目标；撤回来源排除，关联错误明确拒绝。普通任务授权继续锚定 primarySource 和准确任务 fence，归并不转移 owner。

### 精确活动追加

自然消息默认在单个目标存在新契约的活动 Codex 时记录 continue_current 意图；明确 next_turn 则排队。绑定在来源准入时固定为原 invocation/response/cancel 代次，不改绑后来的运行。准备期间等待原句柄；结束或不支持且从未发送时可转入下一轮。Claude CLI/API 不继承其他承载的追加能力。

Codex 使用准确 threadId/expectedTurnId/clientUserMessageId 调用 turn/steer。发送前持久化 InputHandoff、原 Delivery、source 修订/摘要和原 inputRevision；同 turnId 响应才是 accepted，对应 clientId 的 userMessage 才是 read。两者分别保留，内部输入完成能力不声明支持。失败与超时不猜未接受：只有明确未送出或明确协议拒绝才回排；unknown 保持原绑定，重启后不自动发送，当前核查通过原运行的活动句柄只读 thread/read；句柄关闭或跨服务重启后返回未知，不跨会话或跨轮次补猜证据。取消或身份版本变化后的回执仅审计，不改写新绑定或恢复旧输出。accepted 后收到 read 还须核对消费后的 delivery/input 修订；漂移时保留 accepted 和迟到观察，不升级有效读取状态。

协议依据：[Codex app-server turn/steer](https://learn.chatgpt.com/docs/app-server)。实际能力须分别经过本机协议与有界实机验证；未验证的承载保持排队。

### 多人征询

multi_mention 独立于普通多人 @。组头和目标 SourceWork/Delivery 持久化，收集器与 timer 保持进程内；重启丢失的 collecting 组记 lost，目标待办保留，不从局部历史补造完整汇总。目标失败正文（无正文时使用 dispatch-error）可计入结果；取消目标不计，超时不发布部分汇总，迟到不重新打开组。

仅收齐所有目标后发布一次普通系统汇总，不生成 callbackTo 待办，不解析汇总 @。正在参与活动组的成员禁止再创建 multi_mention；普通 A2A 与任务责任仍分开。组取消撤回未消费目标，并请求停止该组准确执行，不影响其他运行。界面展示队列与排序/撤回、停止当前全部运行、输入交付证据及组的 done/timeout/cancelled/lost。

N6 schema 新增 cc_queue_versions、cc_input_exposures、cc_input_handoffs、cc_mention_groups；投递状态变更触发队列修订更新。旧契约、既有业务记录和历史输入原样保留。验收以固定源码摘要交给已建立的独立测试会话，区分模拟、协议和真实 CLI 证据。

## 13 N7 日常工作台与成员账户（2026-11-06 确认实施）

用户明确启动 N7。本轮沿用公开持续会话主干，补齐 U18/U20/U21、R01–R09/R11/R15/R16/R19、D02；不涉及 N8 私密选段转发或 N10 多托管 CLI 身份。产品版本 0.8.0、schema 7，已通过独立验收并部署本地服务，历史执行保留原契约。

### 13.1 工作台契约

- 会话改名、置顶、归档/恢复使用 conversation revision 和 requestId。归档只整理列表，不取消原执行；归档会话须恢复后才能发送新消息。成员配置与会话整理分开提交，旧版本冲突不能覆盖新值。
- 上传入口接收真实 UTF-8 文本（含 Markdown/代码/JSON/CSV），每文件最多 32 KiB，每条消息最多 4 文件且总计 48 KiB。拒绝二进制、无效编码、路径型文件名和伪造的类型；图片/PDF 不在本轮支持范围，界面明确说明。附件元数据与正文分表持久化，绑定 conversationId 和 SHA-256。发送时重新核对附件范围和摘要；可纯附件发送。正文完整串入来源及实际 prompt，不以文件名替代；超出执行输入预算时保留待处理并明确报错，不截断本次请求。
- replyTo 只引用同会话已有稳定 messageId。发送事务核验来源，截取最多 8,000 字符并明确标记截断；引用仅为上下文，不从引用或附件内的 @ 提及路由。用户输入、附件和引用的来源分别可见，主来源 digest 覆盖实际组合正文。
- 新工作区需预览规范路径/目录身份，再显式授权；预览不授予访问权。授权只读、持久化 path/dev/inode/version，避开平台私有数据与产物目录。切换要求当前会话无未释放执行与未投递来源；应用前重验目录及配置/会话版本，派发与每次工作区工具调用再次核对。既有会话继承服务启动时明确设置的工作区；仅填写路径不能切换执行目录。切换后的原生 session 按冻结指纹重验。
- SSE 使用持久事件 ID 补取，客户端事件去重后刷新权威快照；快照游标不提前跳过尚未读取事件。附件上传、工作区授权、受管产物文件回执均有明确来源事件；本轮不宣称能监测任意外部文件修改。

### 13.2 成员、账户与模型契约

- 成员/账户 CRUD 使用稳定 ID、revision、requestId；删除为 tombstone，不物理删除历史作者、契约或证据。成员别名保存时大小写不敏感检测与 ID/姓名/保留提及冲突。停用/删除成员不夺走旧执行身份；未执行投递按既有 held 规则处理。仍被成员或运行时默认引用的账户不可删除，界面说明影响。
- member.accountBinding 为 follow/override（历史记录缺省 override），follow 在下一次 admission 从该 carrier 默认配置解出有效账户。modelBinding 同理；有效账户、模型、effort 进入执行快照，在途执行不读取后续默认值。
- 每个 carrier 的默认配置先 preview，返回受影响 follow 成员、不受影响 override 成员、全局 configurationRevision 和有效期；apply 提交预览 ID 和 requestId，在同一事务比较版本后生效。任何配置变化使旧预览失效。成员新组合模型/effort 必须来自所选账户实际探测目录；目录不能证明模型调用权限，旧已保存配置允许保留，不能伪造已探测状态。
- 账户只保存连接元数据及 API 密钥环境变量引用，不接受明文密钥；API 与 CLI 认证严格隔离，API 路径不回退官方登录。沿用受限数据库权限，不将凭据写日志/SSE/前端存储。
- 无模型调用的显式探测分别报告安装版本、密钥引用是否配置、连接、官方登录身份、模型目录、最近准确账户版本调用、额度。API 模型目录来自所选 endpoint；Codex 官方目录来自 model/list；Claude 官方目录依据本机 CLI 控制协议。目录不支持时明确未取得，不构造通用模型表。未知额度不是 0。异步探测结果以账户版本与请求代次核对，旧结果不能覆盖新状态。
- 官方登录继续由用户在本机官方 CLI 完成；工作台提供准确命令、刷新身份和独立状态。平台不提取订阅 token，不代用户提交 OAuth 授权。官方登录的实机通过必须有真实用户授权和调用证据；本轮自动验收不足时标为未验证。
