# 持续协作交互原型

这是综合实施方案的独立交互演示，供评审预期行为。它没有修改或接入现有平台，也不表示 Clowder 已实现所有演示保证。当前包含 8 个预设场景，覆盖协助、责任转交、上下文、公平调度及恢复。

## 打开方式

直接双击 [prototype.html](prototype.html)，即可离线观看；该文件可单独复制，无须安装依赖或启动服务。修改源码时使用 `index.html`、`styles.css`、`app.js`，三者保持在同一目录。

修改源码后，在仓库根目录执行 `python3 scripts/export-collaboration-prototype.py`，重新生成单文件。

浏览器允许本地存储时，刷新保留当前场景、消息、配额及演示配置；不支持时界面会说明仅使用本页内存。切换场景或点击“重置场景”重新演示，已应用的成员账户配置保留。v4 使用独立存储键，不沿用旧版演示进度。

## 观察路径

| 场景 | 关键观察 |
| --- | --- |
| 01 边工作，边请求协助 | 林与序重叠工作；知会不唤醒；前序依赖满足后才派发；进展与正式结果分开，协助不改变负责人。 |
| 02 并行复核与统一返回 | 固定材料和截止点；两个分支终结后只返回一次。可在序提交后模拟知失败，或继续观察超时和迟到证据。 |
| 03 运行中补充与消费归并 | 对比追加接受不明、完整正文交付、消费归属和待办归并；旧执行失效且确认未接受后，才明确转下一轮。 |
| 04 暂停、积累与继续 | 持久暂停、延迟结果保存、用户明确继续、重复回调归并。暂停后刷新仍保持暂停。 |
| 05 正式转交与责任版本 | 6 步：林提议、序接受、请求停止、核实退出、责任从林 v1 改为序 v2、拒绝旧 v1 交付。停止请求不会直接释放占用。 |
| 06 用户工作与自动链公平调度 | 8 步：序忙时知先领取 A0；资源释放后按 U1 → U2 → A1 → U3 → U4 → A2 领取。队列表展示等待原因、下一候选和配额。 |
| 07 上下文审计与会话重建 | 6 步：材料选择、session 失效、重建、提供本轮输入、后续 v4 延后、v3 结果仅覆盖 v3。全文、摘要、引用、延后和权限过滤分别显示。 |
| 08 结果未知与安全恢复 | 6 步：操作发出、回执丢失、持久暂停、核对、用户明确继续、结算。第 4 步前可选择“发现既有结果”或“确认从未执行”，最后分别为 1 次或 2 次工具尝试。 |

每个场景都可以用“上一步”恢复上一演示快照，用“下一步”再次推进。“上一步”是原型回放能力，会恢复该快照中的演示配置；真实平台不会撤销已发生的外部操作。“步骤记录与状态变化”可以展开，查看各步观察和责任、暂停、返回次数变化。

关系图可点选成员；关系标签可点选，查看请求关系与任务责任的区别。右侧显示选中成员的执行身份，并可展开本轮运行时、配置版本、账户、工作区、session 与下一轮账户。任务负责人按场景变化，转交场景中会实际改变。

公共会话下方直接输入、点击“发送”即可，不需要先选“发送给”或“消息类型”。正文可选用 `@林`、`@序`、`@知`（或 `@lin`、`@xu`、`@zhi`）指定成员，多个目标去重；`@全部` 指向三位成员。发送前的只读提示显示目标与解析理由，无需额外确认。没有 @ 时按最近明确指定的目标、当前任务负责人、最近成功回复成员、会话默认成员依次解析；忙碌不会把目标替换成别人，查看关系图也不改变接收者。普通发送需要回应，不默认仅知会，也不自动建立正式结果请求。知会、协助与正式结果的区别保留在预设场景中观察。

手动发送的明确 @ 目标随刷新保留；切换或重置场景清空该偏好。预设历史里的 @ 属于场景材料，不写入手动偏好，所以正式交接后，没有手动指定目标时接收者会跟随新的负责人。本原型使用独立词式 @：前后以空格或常用中英文标点分隔，邮箱、URL 路径及反引号代码中的 @ 不指定成员；未知名称阻止发送并保留草稿。当前八个场景均含任务；无任务会话的完整交互尚未提供。

自由输入只模拟路由和状态，**不会理解、执行或真实回答任意内容**。分步演示尚未结束时，自定义消息只发表和排队，不改变预设执行；手动派发按钮保持关闭。场景结束后，可从消息投递详情派发排队的普通回复；空闲成员也可在正常发送时领取。执行中、等待退出、核对中的成员均不能再领取，最多同时占用 2 个执行槽。场景 05、08 始终仅保存或排队，避免绕过交接与恢复门槛。这是原型隔离边界，不是完整调度器。

“成员与运行时”可调整跟随默认或成员指定账户；“账户与登录”可预览默认账户切换对成员的影响并应用。当前执行快照保留，下一轮才解析新配置。所有账户均为演示数据，未真实登录。

## 调度规则与模拟边界

- 场景 06 使用全局可运行候选集：先过滤权限、暂停、依赖，再取可用资源上的候选。用户类和自动类均按入队序号 FIFO；最多连续领取 2 个用户工作后，若自动工作可运行，则给它 1 次机会。配额饱和于 2，随原型进度保存。
- 全局并发为 2。等待退出或结果核对中的进程继续占槽；忙成员不阻挡使用独立可用工作区及账户的空闲成员。不抢占正在运行的工具。公平性约束领取机会，前提是候选持续可运行且前项有限，不承诺墙钟等待时间。
- 场景 07 的清单说明“本轮提供什么”，不声称模型理解。权限过滤示例不展示受限正文或敏感标识；精确请求也不能绕过权限。摘要不会将成员提案改成用户决定。
- 场景 08 中没有回执不等于未执行；只有核对既有结果，或确认未执行且旧进程退出后，才能决定如何继续。暂停期间只保存结果，恢复必须由用户明确触发。
- 无模型请求、网络接口、真实登录、密钥读取/输入或真实文件操作。原型中的退出、权限、回执及外部副作用证据均为预设模拟数据。
- “下一步”替代真实模型和服务事件。真实产品按事件调度，无须逐步点击。场景 01–04 的单轮停止仍为简化模拟；场景 05、08 专门展示停止请求与实际退出分离。
- 浏览器本地存储不等同数据库持久化、跨进程恢复或生产级幂等。一次逻辑返回不承诺外部副作用恰好一次。
- 正式结果返回、持久并行组、业务暂停、公平配额及恢复门槛是本项目的独立设计，不能表述为 Clowder 已有保证。
